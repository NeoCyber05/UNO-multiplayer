## Global Constraints

- Commit message **không** có dòng `Co-Authored-By`.
- Build `-std=c11 -Wall -Wextra -Wpedantic -Werror`; mọi lệnh chạy trên Ubuntu 24.04 từ repo root.
- Một thread poll; mọi thời gian truyền vào coordinator/queue dùng **CLOCK_MONOTONIC** (`app_now_ms()`), không dùng CLOCK_REALTIME ngoài `serverTimeMs` của HELLO.
- Actor luôn lấy từ session; payload có `actor`/`seat` ở lệnh trận → `BAD_REQUEST` (coordinator đã làm, dispatcher không tự đọc seat).
- Lỗi nghiệp vụ trả opcode `ERROR` với `payload = {code, message}`; không còn opcode `BAD_REQUEST` trần.
- Request `id <= lastId` trên cùng connection → `ERROR STALE_REQUEST`, không thực hiện.
- Heartbeat: client PING mỗi 5000 ms; server đóng connection không có frame hợp lệ sau 15000 ms (cờ CLI `--heartbeat-ms N` chỉ để test).
- Rớt mạng trong trận không đổi luật (Bách chốt 11/11): không bot thay, timer 20s chạy tiếp; chỉ `MATCH_LEAVE` giao ghế cho bot.
- ELO: khởi đầu 1500, K=32, `lround`, clamp ≥ 0. Solo: so với trung bình 3 người còn lại; team: trung bình đội vs trung bình đối thủ, cùng delta. Unranked/aborted không đổi.
- Hạng: Đồng < 1200, Bạc 1200..1399, Vàng 1400..1799, Kim cương ≥ 1800. Top 20: ELO desc rồi userId asc.
- Queue: FIFO theo mode, không ghép khác mode, không bot trong ranked, party 2 người chỉ ở `2v2`/`side` và luôn cùng đội. Room riêng luôn unranked; chỉ queue 4 human là ranked.
- Native backoff 1/2/4/8 s, cap 8 s, thử đến khi nối được hoặc đóng app; không replay action cũ; token không bao giờ tới JS.
- Snapshot/push/profile không chứa email, password hash, token.

## Review Focus

1. **Login lại khi đang giữ ghế** (LOGIN mới đóng connection cũ rồi bind connection mới): ghế phải giữ, connection mới nhận `GAME_STATE` ngay, không abort trận vì khoảnh khắc 0 human. → test `test_relogin_keeps_seat` ở Task 1.
2. **Response OK bị kẹt sau push**: `matchesHandle` push `GAME_STATE` đồng bộ trước khi dispatcher trả `OK`; client phải nhận cả hai, không mất frame do flush. → `test_play_ok_and_state` ở Task 1.
3. **User trong queue bấm vào phòng / nhận lời mời** (và ngược lại): phải `BUSY`, không tồn tại ở hai nơi. → `test_queue_then_room_busy` ở Task 7.
4. **Connection mạng chập chờn trên desktop**: request JS gửi lúc đang reconnect phải bị từ chối ngay (`DISCONNECTED`), không chờ 10s và không gửi lại khi nối lại. → `test_send_while_disconnected_rejects` ở Task 3.

```c
typedef enum { NS_DISCONNECTED, NS_CONNECTING, NS_RESUMING, NS_CONNECTED } NsState;
typedef enum { NS_FORWARD, NS_DROP } NsVerdict;
typedef struct NetSession NetSession;   /* opaque, ns_create/ns_destroy */

NetSession *ns_create(void);
void ns_destroy(NetSession *s);
void ns_on_connected(NetSession *s);              /* reset wire id = 0, map rỗng, backoff về 0; state = RESUMING nếu có token, ngược lại CONNECTED */
void ns_on_disconnected(NetSession *s);           /* state = DISCONNECTED, xóa map */
NsState ns_state(const NetSession *s);
Status ns_outgoing(NetSession *s, int32_t js_id, const char *type, int32_t *wire_id); /* BUSY khi state != CONNECTED, BAD_REQUEST khi type == "RESUME" */
int32_t ns_internal(NetSession *s, const char *type); /* id wire cho PING/RESUME native */
NsVerdict ns_incoming(NetSession *s, const Envelope *e, int32_t *js_id, json_object **conn_state);
bool ns_has_token(const NetSession *s);
const char *ns_token(const NetSession *s);        /* chỉ native dùng để dựng RESUME */
uint32_t ns_next_backoff_ms(NetSession *s);       /* 1000, 2000, 4000, 8000, 8000, ... */
```

  `ns_incoming`: push (`id==0`) → `NS_FORWARD`, `js_id=0`. Response cho id JS → `NS_FORWARD` với `js_id` đã đổi; nếu request gốc là `LOGIN` và `OK` → lưu `payload.token`; `LOGOUT` OK → xóa token. Response cho id nội bộ → `NS_DROP`; nếu là RESUME: OK → state CONNECTED và `*conn_state = {status:"connected", me}`, ERROR → xóa token, state CONNECTED, `*conn_state = {status:"connected", sessionExpired:true}`. Bảng ánh xạ 256 phần tử; đầy → `ns_outgoing` trả `BUSY`.
